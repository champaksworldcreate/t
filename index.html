How to Debug Facebook and Other Social Media Link Previews

When your page shows the wrong title, old description, missing image, or broken preview on Facebook, LinkedIn, X, WhatsApp, Telegram, and similar platforms, the problem is usually cached metadata or incomplete Open Graph tags. This page explains how to fix that properly.

Concept

What is social media link debugging?

Social media platforms read special metadata from your page to build a share preview card. That usually includes a title, description, image, and canonical URL.

If the preview is wrong, the platform may be using old cached data, or your page may have missing or conflicting metadata.

Why things go wrong
  • Open Graph tags are missing or incomplete
  • The preview image is too small or inaccessible
  • The site was updated, but the platform cached an older version
  • The page blocks crawlers or loads too slowly
  • There are conflicting tags in templates or themes

Main debug tools

These are the most useful places to test and refresh previews across major platforms.

f

Facebook Sharing Debugger

Use this to inspect Open Graph tags, see crawler warnings, and force a fresh scrape when Facebook is showing an older preview.

  • Checks title, description, image, and URL
  • Shows scrape warnings and errors
  • Lets you use “Scrape Again” to refresh cache

Link: developers.facebook.com/tools/debug/

in

LinkedIn Post Inspector

LinkedIn also caches previews. Use this tool after updating a page so LinkedIn re-fetches your metadata.

  • Refreshes the link preview
  • Shows how LinkedIn reads the page
  • Useful after changing title, description, or image

Link: linkedin.com/post-inspector/

X

X / Twitter Card Testing

X preview cards rely on Twitter Card metadata. If the preview is incomplete, check that your twitter:* tags exist and point to valid assets.

  • Tests card behavior
  • Helps validate summary and large-image cards
  • Useful for title, description, and image issues

Add tags like twitter:card, twitter:title, twitter:description, and twitter:image.

WA

WhatsApp preview checks

WhatsApp generally relies on Open Graph tags. In many cases, fixing the metadata and refreshing via Facebook’s debugger helps WhatsApp previews too.

  • Uses page metadata, especially Open Graph
  • Needs a public image URL
  • Often improves after the Facebook refresh step

If WhatsApp is showing an older image, re-check og:image and ensure the image URL is reachable without login.

TG

Telegram preview behavior

Telegram also reads metadata from your page. If a link preview is not correct, make sure your page has valid Open Graph tags and accessible image URLs.

  • Reads title, description, and image
  • Needs proper metadata and public assets
  • Works best with clean canonical URLs
OG

General Open Graph preview tools

Generic preview testers are useful before publishing. They help you see what a shared link may look like even before you post it.

  • Check Open Graph presence
  • Spot missing metadata quickly
  • Useful for general QA before release

Popular examples include tools like metatags.io and similar preview checkers.

Metadata you should add to your page

A good share preview starts with good metadata. Open Graph handles most social platforms, while Twitter Card tags improve X previews.

Essential Open Graph tags

<meta property="og:title" content="Your page title" />
<meta property="og:description" content="Your page description" />
<meta property="og:image" content="https://example.com/preview.jpg" />
<meta property="og:url" content="https://example.com/page" />
<meta property="og:type" content="article" />

Essential Twitter Card tags

<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content="Your page title" />
<meta name="twitter:description" content="Your page description" />
<meta name="twitter:image" content="https://example.com/preview.jpg" />

Common problems and fixes

Problem Likely reason Fix
Wrong title Old cached metadata or conflicting title tags Update og:title and re-scrape the page
Description not updated Platform cache still holds the old description Refresh with the platform’s inspector/debugger
Image not showing Image URL is blocked, too small, broken, or not public Use a public HTTPS image URL and test it directly in the browser
Blank preview Metadata missing or crawler unable to fetch page Add OG tags and check server/crawler accessibility
Different platforms show different previews Each platform caches independently and may read tags differently Test each one separately and keep metadata consistent
Preview still old after update Page or CDN cache still serving older HTML or images Clear site cache, then use platform refresh tools again

Important image tips

  • Use a large preview image, ideally around 1200 × 630 pixels
  • Keep the image public and accessible without login
  • Use HTTPS, not HTTP
  • Avoid filenames that change without updating the URL cleanly
  • Do not hotlink unstable images from third-party pages

Important page tips

  • Make sure the page has one clean canonical URL
  • Do not output conflicting OG tags from multiple templates
  • Make sure the final deployed HTML contains the tags, not just your local copy
  • Check robots rules if bots cannot read the page
  • Test the exact published URL, including trailing slash differences if relevant

A practical debugging workflow

Use this order when a shared preview is wrong.

  1. Open the exact published page URL in your browser and confirm it works.
  2. View the page source and verify that the final HTML includes all Open Graph tags.
  3. Check that the og:image URL opens directly.
  4. Confirm the image is HTTPS and large enough for preview cards.
  5. Run the page through Facebook Sharing Debugger.
  6. Click “Scrape Again” if Facebook shows stale data.
  7. Run the same link through LinkedIn Post Inspector.
  8. Check Twitter Card metadata if X previews are wrong.
  9. Test the link again inside WhatsApp or Telegram.
  10. If it is still wrong, clear site cache or CDN cache and repeat the checks.

Ready-to-use template

You can place something like this inside the <head> of your article page or layout file. 

<title>My Article Title</title>
<meta name="description" content="A short description of the page." />

<meta property="og:title" content="My Article Title" />
<meta property="og:description" content="A short description of the page." />
<meta property="og:image" content="https://example.com/assets/preview.jpg" />
<meta property="og:url" content="https://example.com/my-article" />
<meta property="og:type" content="article" />

<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content="My Article Title" />
<meta name="twitter:description" content="A short description of the page." />
<meta name="twitter:image" content="https://example.com/assets/preview.jpg" />

Final note

If you are publishing with GitHub Pages, Jekyll, Blogger, or a custom HTML site, the best approach is to put these meta tags into your shared layout so every page automatically gets clean social preview metadata. That reduces broken previews across Facebook, LinkedIn, X, WhatsApp, Telegram, and other platforms.

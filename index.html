Section 1

Problem and Goal

Foundation first

The challenge

Suppose you have a huge dataset of integers. It may contain up to 1 crore numbers, which means 10 million values. Loading everything into memory and sorting it in one shot may be uncomfortable or inefficient. So the project explores a different idea: process the data file by file.

Goal of the active program

Read all files in a folder, find the minimum and maximum inside each file, and then combine those results to compute the overall minimum and maximum.

Goal of the backup program

Start with one giant file, split it into smaller files by value range, and keep splitting recursively until every file becomes manageable.

Section 4

The Backup System: Recursive Range Partitioning

Big-data design

The main idea

Instead of sorting a huge file directly, the backup system splits the file by numeric range. It uses the midpoint of the current range and sends numbers into two child files: one for lower values and one for upper values.

Generated first file

Data0,-1000,1000,10000000

This means file name Data0, minimum possible value -1000, maximum possible value 1000, and size 10000000.

Stopping rule

if (fileSize < maxSize) stop;

If a file becomes smaller than the threshold, recursion ends for that file.

Demonstrates counting sort separately. It is not the active large-file engine, but it shows another sorting idea.

Section 6

Pseudocode

Algorithmic view

6.1 Active file scan

function getMinMax(file):
    read first number
    min = first number
    max = first number

    while more numbers exist:
        n = next number

        if n > max:
            max = n

        if n < min:
            min = n

    return (min, max)

6.2 Active full workflow

function processAllFiles(directory):
    files = getAllFiles(directory)
    results = []

    for each file in files:
        summary = getMinMax(file)
        results.append(summary)

    globalMin = results[0].min
    globalMax = results[0].max

    for each result in results:
        if result.min < globalMin:
            globalMin = result.min
        if result.max > globalMax:
            globalMax = result.max

    print(globalMin, globalMax)

6.3 Recursive partitioning

function breakFile(file, maxSize):
    metadata = readMetadata(file)

    if metadata.size < maxSize:
        return

    avg = (metadata.min + metadata.max) / 2

    create child1
    create child2

    for each value x in file:
        if x < avg:
            write x to child1
            update child1 metadata
        else:
            write x to child2
            update child2 metadata

    delete original file

    rename child1 using child1 metadata
    rename child2 using child2 metadata

    breakFile(child1, maxSize)
    breakFile(child2, maxSize)
Section 7

Complexity Analysis

Time thinking

Active program

Let N be the total count of numbers across all files and F be the number of files.

Scanning all numbers: O(N) Combining file summaries in current code: O(F²) Cleaner combine method possible: O(F)

Backup recursive system

Each splitting level scans data again, and the depth depends on how the value range gets narrowed. A rough intuitive view is O(N log R), where R is the value range.

Important observation

The active system is a min-max reducer, not a full sorter. The backup system is closer to a file-based partitioning framework for very large data.

Section 8

Strengths and Limitations

Critical view

Strengths

File-based processing avoids loading everything at once. Local summaries are simple and effective. Range-based recursive splitting is a smart way to shrink huge problems into smaller ones.

Limitations

The current active code does not sort the entire dataset. There is no merge stage. The combine phase is more repetitive than necessary. The system can also be improved with safer naming and stronger file-handling practices.

Section 11

Final Summary

Takeaway

One-line summary

This project studies how very large numeric datasets can be processed file by file: the active code computes local and global min-max values, while the backup design recursively partitions one giant file into smaller range-based files.

What you should remember

File-based thinking helps when full in-memory processing becomes difficult. Local summaries are cheap. Recursive partitioning narrows both file size and numeric range.

Best next upgrade

Add a final stage that sorts or merges the final child files. That would turn the design into a more complete large-data external sorting system.

Day 1 — Debugging & Testing in the Browser

Today you’ll learn the real superpower of JS developers: browser DevTools. You’ll debug errors, inspect values, pause code with breakpoints, test APIs, and verify storage/caching.

Shortcut: open DevTools quickly → Ctrl + Shift + I (Windows/Linux), or Cmd + Option + I (Mac).

1) Debugging mindset

Debugging is not “guessing” — it’s a repeatable process

4-step process:

  • Reproduce the bug (same steps every time)
  • Observe what you see (error message / wrong value)
  • Isolate the cause (which line? which input?)
  • Fix + verify (test again, add guards)

Golden rules:

  • Trust the browser: read the exact error
  • Check inputs before you blame logic
  • Use breakpoints, don’t spam logs forever
  • After fix: test “happy path” + “edge cases”

2) Console essentials

Console methods you’ll use daily

These help you inspect values quickly.

// Basic logging
console.log("Hello");
console.info("Info");
console.warn("Warning");
console.error("Error");

// Inspect objects better
console.table([{id:1,name:"A"},{id:2,name:"B"}]);
console.dir(document.body);

// Group logs
console.group("Login flow");
console.log("Step 1: validate");
console.log("Step 2: fetch");
console.groupEnd();

// Measure time
console.time("fetch");
console.timeEnd("fetch");

// Assertions
console.assert(2 + 2 === 4, "Math broken");
Tip: In Console you can also run JS directly like a scratchpad: document.querySelector("h1").textContent

3) Common errors (and what they really mean)

Read error messages like a pro

1
Uncaught ReferenceError — “x is not defined”
You used a variable that doesn’t exist (typo / scope issue).
2
Uncaught TypeError — “cannot read properties of null”
Your selector returned null (element not found / runs too early).
3
SyntaxError — “Unexpected token …”
A missing bracket/quote, or wrong JS syntax.
4
Network Error / CORS
Request blocked or URL/API issue. Use the Network tab.

Example: null element bug

// Bug:
const btn = document.querySelector("#start"); // returns null
btn.addEventListener("click", () => alert("Hi")); // TypeError

// Fix ideas:
const btn = document.querySelector("#start");
if(btn) btn.addEventListener("click", () => alert("Hi"));

// OR run after DOM loads:
window.addEventListener("DOMContentLoaded", () => {
  document.querySelector("#start").addEventListener("click", () => alert("Hi"));
});

4) Breakpoints (the real power)

Pause code and inspect everything

Where: DevTools → Sources

  • Click a line number → adds a breakpoint
  • Reload page → it will pause there
  • Inspect variables in Scope panel
  • Use Step over, Step into, Step out

Bonus:

  • Conditional breakpoint: pause only when condition is true
  • Logpoint: log without changing code
  • Debugger statement: put debugger; in code to pause
function total(price, qty){
  debugger;           // DevTools will pause here
  return price * qty;
}
console.log(total(10, 3));

5) Testing APIs (Network tab)

Verify fetch requests, status codes, and JSON

When your app calls an API, the Network tab is your truth.

  • DevTools → Network → filter Fetch/XHR
  • Click a request → check Status, Response, Headers
  • Use “Disable cache” while DevTools is open for clean testing
// Quick fetch test (run in console)
fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then(r => r.json())
  .then(console.log)
  .catch(console.error);

6) Testing storage & state

localStorage, sessionStorage, cookies

Where: DevTools → Application tab

  • Local Storage: saved even after closing tab
  • Session Storage: cleared when tab closes
  • Cookies: auth/session and server-related data

Common debug checks:

  • Is your key saved?
  • Is JSON valid?
  • Do you clear old data when schema changes?
// localStorage quick tests
localStorage.setItem("pp_demo", JSON.stringify({x:1, at:Date.now()}));
JSON.parse(localStorage.getItem("pp_demo"));
localStorage.removeItem("pp_demo");

7) Browser testing habits

How to “test” without a full testing framework

Manual test checklist:

  • Happy path works (normal input)
  • Edge cases: empty, huge, invalid values
  • Refresh page: state remains as expected
  • Slow network / offline cases

Quick “micro-tests”:

  • Use console.assert
  • Write small pure functions and test in console
  • Keep logs temporary—remove after fix
// Micro-tests
function clamp(n, min, max){
  return Math.max(min, Math.min(max, n));
}
console.assert(clamp(5, 0, 10) === 5, "clamp(5) failed");
console.assert(clamp(-2, 0, 10) === 0, "clamp(-2) failed");
console.assert(clamp(99, 0, 10) === 10, "clamp(99) failed");
